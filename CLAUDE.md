## Project Summary

**PHPCrypt** is a Jasypt-like encryption library for PHP, part of a cross-language encryption family.

## Cross-Language Family (ALL SAME ENC() FORMAT!)

| Project | Repository | Language | Package |
|---------|-----------|----------|---------|
| GoCrypt | github.com/farizfadian/gocrypt | Go 1.21+ | Go module |
| PyCrypt | github.com/farizfadian/pycrypt | Python 3.8+ | pycrypt-jasypt (PyPI) |
| NodeCrypt | github.com/farizfadian/nodecrypt | Node.js 18+ | nodecrypt-jasypt (npm) |
| **PHPCrypt** | github.com/farizfadian/phpcrypt | **PHP 8.1+** | **farizfadian/phpcrypt** |
| Jasypt | jasypt.org | Java | org.jasypt (Maven) |

**USE JasyptEncryptor WHEN JAVA MUST READ THE VALUE.** All three modes are shared with the Go, Rust, Node and Python libraries; only `JasyptEncryptor` is shared with Java Jasypt.

**GoCrypt is the reference implementation.** If PHPCrypt and GoCrypt disagree, PHPCrypt changes. Never change a wire format on your own.

## Three Encryptors

| Class | Algorithm | Java Compatible? | When to Use |
|-------|-----------|------------------|-------------|
| `Encryptor` | AES-256-GCM | NO | Only family libraries read the value |
| `JasyptEncryptor` | PBEWithMD5AndDES | YES | A Java service reads the same config |
| `JasyptStrongEncryptor` | PBKDF2-SHA256 + AES-256-CBC (family format) | NO | Stronger CBC mode inside the family |

### Wire Formats (must match GoCrypt byte for byte)

| Class | Key derivation | Cipher | base64 payload |
|-------|----------------|--------|----------------|
| `Encryptor` | PBKDF2-HMAC-SHA256, 10000 iterations, key 32 bytes | AES-256-GCM, no AAD | `salt(16) ‖ nonce(12) ‖ ciphertext ‖ tag(16)` |
| `JasyptEncryptor` | PBKDF1-MD5, 1000 iterations: bytes 0-7 key, 8-15 IV | DES-CBC, PKCS5 | `salt(8) ‖ ciphertext` |
| `JasyptStrongEncryptor` | PBKDF2-HMAC-SHA256, 1000 iterations, 48 bytes: 0-31 key, 32-47 IV | AES-256-CBC, PKCS7 | `salt(16) ‖ ciphertext` |

- `Encryptor` key size selects the cipher, as in GoCrypt: 16 = AES-128, 24 = AES-192, 32 = AES-256. `encrypt()` rejects any other size.
- Passwords and plaintext are UTF-8 bytes. The string `"0"` is a valid password and a valid value: compare with `=== ''`, never with `empty()`.
- Real Jasypt `PBEWithHmacSHA256AndAES_256` writes `salt ‖ iv ‖ ciphertext` with a random IV. That is not the family strong format. Moving to it would be a coordinated release of all five libraries.

### Constructor Signatures

```php
// AES-GCM (family only, not Java)
new Encryptor(string $password, int $iterations = 10000, int $saltSize = 16, int $keySize = 32)

// Jasypt default (Java compatible) - PBEWithMD5AndDES
new JasyptEncryptor(string $password, int $iterations = 1000)

// Family strong format (NOT Java compatible) - AES-256-CBC with PBKDF2
new JasyptStrongEncryptor(string $password, int $iterations = 1000, int $saltSize = 16)
```

Each encryptor has a private, `@internal` deterministic core (`encryptWithSaltAndIv()` in `Encryptor`, `encryptWithSalt()` in the other two). `encrypt()` passes fresh random values to it. Only `GoldenVectorTest` calls it directly, through reflection, to reproduce GoCrypt's fixed-salt vectors. Do not make it public.

### Common Methods (all three encryptors)
```php
encrypt(string $plaintext): string              // Returns base64
encryptWithPrefix(string $plaintext): string    // Returns ENC(base64)
decrypt(string $encoded): string                // Decrypts base64
decryptPrefixed(string $value): string          // Decrypts ENC(base64)
decryptMap(array $map): array                   // Decrypt all ENC() values
decryptAllInString(string $input): string       // Decrypt all ENC() in a string
```

## OpenSSL Legacy Provider (CRITICAL)

### The Problem
JasyptEncryptor uses DES-CBC (PBEWithMD5AndDES). OpenSSL 3.0+ (used by PHP 8.2+ on some platforms) disables DES by default.

### CI Solution: Custom openssl.cnf
CI creates a custom openssl.cnf file and sets `OPENSSL_CONF` env var. This works uniformly across all platforms:

**Unix (Linux/macOS):**
```bash
printf "openssl_conf = openssl_init\n[openssl_init]\nproviders = provider_sect\n..." > openssl-legacy.cnf
echo "OPENSSL_CONF=${{ github.workspace }}/openssl-legacy.cnf" >> $GITHUB_ENV
```

**Windows (PowerShell):**
```powershell
$conf = "openssl_conf = openssl_init`n[openssl_init]`nproviders = provider_sect`n..."
$conf | Set-Content -Path $confPath -NoNewline
echo "OPENSSL_CONF=$confPath" >> $env:GITHUB_ENV
```

### Windows: OPENSSL_MODULES
On Windows, `OPENSSL_CONF` alone is not enough: OpenSSL must also find `legacy.dll`. The official PHP for Windows builds ship it in `extras\ssl` inside the PHP folder. Set `OPENSSL_MODULES` to that folder and DES works (checked with PHP 8.5.12, OpenSSL 3.5.9, on 2026-11-19). The Windows CI jobs do not set it.

### Test Graceful Degradation: skipIfDesNotAvailable()
**A skipped test is not a passed test.** The matrix jobs may skip DES; the `interop` job enables the legacy provider on Linux and runs with `--fail-on-skipped`, so DES is exercised for real there.

Every test that needs DES calls this helper from the `DesAvailability` trait (`tests/DesAvailability.php`):
```php
private function skipIfDesNotAvailable(): void
{
    $ciphers = openssl_get_cipher_methods();
    if (!in_array('des-cbc', $ciphers, true)) {
        $this->markTestSkipped('DES-CBC not available');
    }
    // Also check that it actually works (some systems list it but fail)
    $result = @openssl_encrypt('test', 'des-cbc', '12345678', OPENSSL_RAW_DATA, '12345678');
    if ($result === false) {
        $this->markTestSkipped('DES-CBC listed but not functional');
    }
}
```

**Why two checks?** Some systems list `des-cbc` in `openssl_get_cipher_methods()` but the actual encrypt call fails because the legacy provider DLL/SO is missing (common on Windows with shivammathur/setup-php).

## Known Issues & Fixes Applied

### 1. Windows PHP 8.2/8.3 - DES May Not Work
`shivammathur/setup-php` on Windows doesn't always include the OpenSSL legacy provider DLL. DES tests are gracefully skipped via `skipIfDesNotAvailable()`.

### 2. macOS sed -i Incompatibility (Fixed)
BSD `sed -i` requires a backup extension argument unlike GNU sed. Fixed by using `printf` to create openssl.cnf instead of `sed -i` on existing files.

### 3. CBC Modes: Wrong Password - No Guaranteed Throw
DES-CBC and AES-CBC have NO integrity check (unlike AES-GCM). Decrypting with a wrong password usually fails the padding check, but about 1 time in 256 it returns garbage instead of throwing. Tests must not expect an exception every time: `testJasyptWrongPasswordNeverReturnsPlaintext` accepts both outcomes.

### 4. Release: Pushing a Tag IS a Release
Packagist auto-syncs from GitHub via webhook (seen working on 2026-11-19: a pushed branch appeared on Packagist within minutes). So pushing a tag publishes a version:
```bash
git tag v1.x.x
git push origin v1.x.x
# Packagist auto-syncs (no token needed)
```
Before tagging:
- Update `VERSION` in `bin/phpcrypt` and add the version and date to `CHANGELOG.md`.
- Tag the commit on `main` whose CI run is green, not a branch.
- Do NOT add a `"version"` field to `composer.json`. It was removed in 1.0.1: Composer takes the version from the tag, and it skips a tag that disagrees with a hard-coded field, saying so only in `-vvv` output.

`v1.0.0` also has a GitHub Release; create one for each new tag with `gh release create <tag> --verify-tag`.

### 5. `JasyptStrongEncryptor` Is Not Java Compatible
It is the family strong format. Real Jasypt 1.9.3 `PBEWithHmacSHA256AndAES_256` cannot read it and it cannot read Jasypt (confirmed 2026-11-19, pinned by two tests in `LiveInteropTest`). Decrypting a real Jasypt value does not even throw: the result is 16 bytes of garbage followed by the plaintext. Do not fix this in PHPCrypt alone.

### 6. `Encryptor` Key Sizes Other Than 32 in PHPCrypt 1.0.0
1.0.0 always used `aes-256-gcm`. OpenSSL zero-padded a shorter key and cut a longer one, so `keySize` 16 or 24 produced values GoCrypt could not read. Later versions write AES-128/192 as GoCrypt does, and `decrypt()` falls back to the 1.0.0 layout so stored values keep working (`BackwardCompatibilityTest`). Keep that fallback. Key sizes were checked against GoCrypt only: the family command-line tools have no key-size option.

### 7. `ConfigLoader` Always Uses `Encryptor`
It cannot load a file whose values were encrypted with `JasyptEncryptor`, and a value that fails to decrypt is returned as the literal `ENC(...)` text without an error. For Jasypt-encrypted files use `JasyptEncryptor::decryptMap()` or `decryptAllInString()`.

## Cross-Language Testing Status

Only the rows below were executed. A format that matches on paper is not a test: PyCrypt 1.0.0 looked right and was not.

| Counterpart | Mode | Direction | Result |
|-------------|------|-----------|--------|
| GoCrypt v1.0.0 golden vectors | all three | decrypt 12 values; reproduce 17 fixed-salt values byte for byte | ✅ every CI job (`GoldenVectorTest`); the DES ones are skipped on Windows with PHP 8.2/8.3 |
| GoCrypt v1.0.0, `Encryptor` key sizes 16, 24, 32 | default | decrypt 6 values; reproduce 6 fixed-salt values that GoCrypt itself decrypted | ✅ every CI job (`GoldenVectorTest`). PHPCrypt → GoCrypt was also run live once, 2026-11-19 |
| GoCrypt v1.0.0 CLI | all three | both | ✅ CI `interop` job |
| RustCrypt v1.0.0 CLI | all three | both | ✅ CI `interop` job |
| NodeCrypt 1.0.1 CLI | all three | both | ✅ CI `interop` job |
| PyCrypt 1.0.1 CLI | all three | both | ✅ CI `interop` job |
| Java Jasypt 1.9.3 on JDK 25, `PBEWithMD5AndDES` | `--jasypt` | both | ✅ CI `interop` job |
| Java Jasypt 1.9.3 `PBEWithHmacSHA256AndAES_256` | `--jasypt-strong` | both | ❌ by design, see Known Issue 5 |

- Each live round trip uses five cases: ASCII, punctuation, 200 characters, non-ASCII text with an emoji, and a non-ASCII password.
- The same suite passed on Windows on 2026-11-19 (PHP 8.5.12, OpenSSL 3.5.9 with the legacy provider, JDK 25, Node 24, Python 3.14), 0 skipped.
- **Non-ASCII passwords depend on the JDK.** With `PBEWithMD5AndDES`, JDK 21 (Temurin, in CI) throws `Password is not ASCII` before Jasypt does any work. JDK 25 accepts the password and uses its UTF-8 bytes, as the family does. That is why the interop job runs JDK 25. On a JDK that rejects it, `LiveInteropTest` skips that one case with a message.
- Not tested: Jasypt inside a Spring Boot application, and PHP on macOS against the live tools (the macOS jobs run the golden vectors only).
